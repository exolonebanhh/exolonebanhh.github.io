Overview

The Acai Procurement System is a procurement platform built for a sourcing business that buys products from suppliers on behalf of customers. It covers the complete commercial cycle — customers, products with variants, suppliers, procurement plans, purchase orders, receiving, returns, and invoicing — wrapped in a dashboard that surfaces balances, debts, and pending work at a glance.

Backend: Python Flask · Database: PostgreSQL · Frontend: vanilla JavaScript SPA. Current release v2.1.3.

Nine Functional Modules

  • Customers — auto-generated codes (AC0001…), balance top-ups, full transaction history.
  • Products — SKU generation, multi-spec variants (color, size), archiving and restore.
  • Suppliers — finance (credit limits, payment terms, deposit ratios), quality & compliance, logistics, relationship data, and a built-in debt ledger.
  • Procurement plans with a submit → approve → execute workflow.
  • Purchase orders — multi-supplier orders, payment recording with receipt uploads, and logistics tracking.
  • Receiving — smart quantity balancing (received + short + damaged must reconcile), quality inspection, and automatic return generation when goods go missing or arrive damaged.
  • Returns — categorized by reason, automatically posted into the supplier debt ledger.
  • Invoices — multi-PO linking with automatic subtotal, discount, tax, markup, and commission calculations.
  • Dashboard — stat cards, recent plans, customer balance ranking, and supplier debt overview.

Security Audit & Hardening

Remediated critical vulnerabilities by securing over 155 previously unauthenticated API endpoints through a global JWT authentication gate (before_request) and role-based access control across all four roles.

  • Full security scan performed: 200+ database queries verified as safely parameterized — SQL injection and XSS checks passed.
  • File upload security: restricted file types, secure_filename() validation, timestamped storage.
  • JWT secret persisted to file — fixed login breakage in Chrome Incognito across Chrome, Edge, Safari, and Firefox.
  • CSRF accepted as documented risk for the API-first design.

Workflow & Database

  • Resolved legacy PostgreSQL schema issues through idempotent SQL migrations, restoring the end-to-end workflow from PR to invoice.
  • 172 REST API endpoints · 36 PostgreSQL tables.

Testing
